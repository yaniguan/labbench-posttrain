# Lab post-training v0: design mapped to code

Status: **built** means implemented and exercised locally on CPU; **partial** means a working component with a named gap; **TODO** means no working implementation. A smoke pass establishes that a pipeline runs, not that it improves science or robot performance. **GPU results: PENDING (A100 Colab).**

## Dataset and evidence

The common unit is `src/labpt/schema.py::Record`, serialized by `labpt.io::{to_row,from_row}` into `data/v0/records.parquet`. It keeps `source`, `source_id`, `source_url`, `license`, `method`, `instrument`, `conditions`, `units`, `raw`, and an explicit `provenance`. Do not average these evidence types together as if they were interchangeable measurements.

| Idea | Status | Code and limits |
|---|---|---|
| Measurement / compute / ML prediction / human annotation separation | built | `schema.py::Provenance`; ingesters set the label. `ingest_chembl.py` separates activity measurements, deterministic properties, and fitted predictions. `ingest_pubchem.py` separates assay results, computed properties, and XLogP. `ingest_qm9.py` labels DFT as compute. `ingest_messy.py::eln` labels notebook text as human annotation. These are source classifications, not proof that every source label is correct. |
| Modality, physical scale, source | built | `schema.py::{Modality,Scale,Record}` keeps these as separate axes. Record modality can be reaction, robot episode, spectrum, run log, image, table, note, bioassay, or molecular property. `scripts/make_overview.py` tabulates the real files. QM9 currently uses the ingester's `atomic` scale label; it is not an atomic-resolution measurement. |
| Annotation origin and scale/modality context | partial | `schema.py::Annotation` stores key/value, annotator and `auto`. An annotation inherits modality, scale and source through its parent record, rather than duplicating them. `annotate.py::annotate` supplies weak rule labels. `ingest_messy.py::alab_ledger` retains source-author human notes (`auto=False`); `annotate_llm.py` outputs automatic LLM labels. No cross-lab annotation agreement or feedback UI. |
| Real protocols and failed runs | built | `ingest_ord.py` keeps procedures and measured yield; `protocol_parser.py::parse_procedure` creates weak action labels. `ingest_messy.py::{alab_ledger,ada_log,rodare,chemos_log}` preserves unsuccessful runs, dosing errors, warnings, aborts, and incomplete results. Unknown outcome stays null. A warning is not necessarily a scientific failure. |
| Raw instrument data and protocols together | partial | `ingest_messy.py::{alab_xrd,darus,plate_endpoint,plate_kinetic,microscopy}` parses XRD, HPLC, plate exports, curves and image patches. `Record.raw` points to an excerpt or local sample; original source URLs remain. `data/v0/raw_samples` is small, browsable context. Alignment to individual protocol steps, complete raw streams, video and protocol version history are TODO. |
| Validation, deduplication, group split | built | `scripts/build_dataset.py` validates records and calls `Record.dedup_key` and `splits.py::assign_splits`. Default grouping follows the recorded `group_key` (scaffold, ORD dataset, task, plate, target, etc.). It is not uniformly a lab, assay, or element-system split. `datacard.json` reports the actual counts and group overlap. |

Human-authored text is not an experimental readout. Human notes attached to a measurement do not change that record's evidence type. Automatic annotations and deliberately corrupted preference answers are training labels, not additional laboratory observations. The current source licenses and small sample sizes are listed in `DATA_LICENSES.md` and `docs/dataset_overview.md`.

## Scientist track

| Idea | Status | Code and limits |
|---|---|---|
| Representation learning | partial | `scientist/train_encoders.py` trains `encoders.py::{MolEncoder,SpectrumEncoder,ImageEncoder}`. Molecules use Morgan fingerprints and QM9 regression; curves use masked reconstruction; images use denoising. `scientist/data.py::{molecules,spectra,images}` loads real arrays. The image demo has one source image and trains on all patches; it has no independent image generalization claim. |
| Modality/text alignment | partial | `scientist/train_align.py` uses contrastive loss over molecule/assay text and curve/method text; `TextEncoder` hashes text. Retrieval metrics compare held-out pairs. Repeated descriptions and weak pair semantics limit interpretation. This is not a pretrained scientific multimodal foundation model. |
| Multimodal language training | partial | `scientist/train_projector.py::{batch,forward}` projects frozen molecule embeddings to soft tokens, prepended to an LLM, with optional LoRA. The prompt omits SMILES; labels are QM9 computed properties. Saves projector and, if enabled, LLM adapter. Spectrum/image-to-LLM projection and a complete multimodal inference loader are TODO. |
| Distillation | partial | `scientist/distill.py` minimizes teacher/student forward KL plus causal CE on real task text. Teacher and student must use compatible token IDs. Configs use one Qwen family; copying the shared vocabulary prefix does not make unrelated tokenizers compatible. Teacher quality has not been established. |
| LoRA / QLoRA and SFT | built | `scripts/train_sft.py` uses TRL SFT and PEFT LoRA; optional 4-bit QLoRA is configured for GPU use. `tasks.py::{provenance,property_qa,outcome}` builds Scientist tasks. CPU smoke exercises LoRA; QLoRA and A100 behavior remain untested. |
| DPO and ORPO | built | `scripts/train_pref.py` consumes `tasks.py::make_pairs` outputs. Wrong-provenance and corrupted-action negatives are deliberate corruptions, explicitly labeled by kind. Success/failure pairs use real outcomes within a dataset/element family and the same split. Family matching does not establish the same transformation or causal superiority; tighter matching and human review are TODO. |
| Reward model | partial | `scripts/train_rm.py` trains a sequence scorer with pairwise preferences and saves its adapter. Current Scientist RM configs use wrong-provenance pairs; Operator configs use coarse actions/outcomes. This is not an assay-calibrated RM. |
| GRPO | built | `scripts/train_grpo.py::{r_schema,r_overlap,r_provenance,r_units}` supplies separate verifiable rewards to TRL GRPO with `kl_beta`. These are weak protocol/evidence checks; no T3 assay quality reward enters GRPO. |

Each A100 config currently defines an independent baseline from its stated base model. SFT adapters are not silently loaded into DPO, RM or GRPO. A sequential experiment must explicitly merge/load the desired checkpoint and record that choice.

## Tiered rewards

| Tier | Status | Code and interpretation |
|---|---|---|
| T1: cheap executability | partial | `actions.py::{validate_action,ACTION_SCHEMA,ActionResult,run_log_to_reward_pairs}` validates strict instrument calls, Data/Error results and observed completion. Supported calls: aspirate, dispense, move, heat, wait, measure; parameter names carry units. Empty, skipped and merely retried runs get no success credit. Pass planned step IDs to penalize omitted steps. The default volume/temperature bounds are example limits, not a calibrated instrument driver. No physical executor or liquid inventory simulator is built. |
| T1: coarse protocol checks | built | `rewards.py::{schema_valid_actions,action_overlap,unit_consistent}` checks known verbs, a temperature bound, reference step coverage and evidence units. `schema.Action` remains permissive for weak historical labels. A coarse action passing this check has not passed the strict instrument schema or hardware execution. |
| T1: Operator geometry | partial | `constraints.py::check_constraints` checks all waypoints against trusted workspace bounds and joint limits, and checks full point segments against axis-aligned collision boxes with `segment_hits_box`. `operator/check_constraints.py::main` exposes its 0/1 reward. This is a swept-point check, not full arm collision detection, IK, velocity/acceleration checking, or certification for execution. |
| T2: verifiable historical answers | partial | `tasks.py::{outcome,property_qa,safety_failure,provenance}`, `rewards.py::total_reward`, `scripts/eval_llm.py` compare with historical answers. Outcome thresholds are weak labels (for example ORD yield >=20%). Some failure tasks include reported yield and are interpretation/extraction tasks. Outlier-well tasks, calibrated numerical tolerances and validated failure-cause attribution are TODO. |
| T3: assay-calibrated RM | TODO | `scripts/assay_quality.py::{replicate_stats,z_prime,quality_report}` is built and computes available sample CVs. Z' = 1 - 3*(SD_pos+SD_neg)/abs(mean_pos-mean_neg), with sample SD. Current endpoint exports label BLK and SPL1 dilution samples, but no positive controls; Z' is unavailable, not inferred from high samples. Growth H/L labels do not establish replicates; one blank is insufficient. `docs/assay_quality.md` reports the real limitations. Connecting quality labels to an RM, dose-response consistency, signal/noise and prospective goal-hit calibration remains TODO. |

T1 rewards mean structure/completion, not a correct scientific result. T2 labels must use the correct evidence origin. T3 needs assay-specific controls and an agreed goal before it can calibrate preferences. Do not use model-generated success reports as trusted execution evidence.

The CPU smoke model is random and often emits no valid JSON. Zero GRPO reward/loss can therefore be a real smoke result; it is not evidence of successful RL. `scripts/smoke_all.py` preserves losses, return codes, wall times and profile summaries rather than substituting successful values.

## Operator track and Medra lessons

The reference is the supplied local research report, `/workspace/medra_research/report.md`, dated 2026-11-03. It describes public interfaces and planner forks, not a public Medra post-training implementation. The Foxglove-to-MCAP interpretation is an inference in that report.

| Idea borrowed / Operator component | Status | Code and limits |
|---|---|---|
| JSON-Schema Action with Data/Error result | built | `actions.py` exposes discriminated `InstrumentAction` schemas, `RESULT_SCHEMA`, and `RunEvent`. Success requires Data and no Error; error/skip/retry requires a reason and no Data. `retried` means a retry was requested, not that it worked. This borrows the interface pattern described for Medra api-starter; no Medra code or service is required. |
| Errors + skip/retry -> verifiable rewards and DPO | partial | `actions.py::run_log_to_reward_pairs` scores the terminal result of each planned step. It makes a preference only when the same run/step/call has an actual error prefix and a later observed ok prefix. It preserves observed attempts and creates no fake successful trace. These pairs teach trace/recovery structure, not a proven better causal action; real typed hardware traces and audited recovery decisions are not yet in v0 training data. |
| High-level skills, waypoints and constraints | partial | `constraints.py::{OperatorPlan,Waypoint,PlanConstraints,ConstraintSpec}` supports model-proposed skills, waypoints and extra avoid-box constraints; caller-owned workspace/joint/obstacle limits always remain in force. `operator/check_constraints.py` scores them. Existing protocol SFT emits coarse primitives and BC emits dataset action vectors; neither is yet trained to emit this complete skill/waypoint format. Tool-orientation constraints, IK via a robot model, OMPL planning and retiming are TODO. |
| IK/collision executability as reward | partial | Collision-box and joint/workspace rewards are implemented in `check_constraints`. Full IK success and link-level collision reward require robot URDF/MJCF and a real planner. Do not describe box tests as IK. This follows the report's high-level planner/IK layering. |
| Behavior cloning | built | `operator/train_bc.py::{tensors,training loop}` trains an MLP on real state/action frames for one robot repo at a time. Reports held-out MSE and a train-mean baseline. State/action dimensions do not imply joint or Cartesian units; geometry checks are not applied without an explicit robot frame/layout. |
| World model | partial | `operator/world_model.py::WM.forward` predicts next state via normalized state deltas and reports open-loop rollout error versus copy-state. It is a low-dimensional model, not a digital twin. It is not connected to live execution or used as a learned reward in GRPO. |
| MCAP-style logs | built | `logs.py::{LogWriter,read_log}` appends/reads `{topic,timestamp,message}` JSONL; timestamp is Unix nanoseconds, topics may be action/state/readout/video-reference. This is not binary MCAP and needs no mcap dependency. `tests/test_actions_constraints_logs.py` exercises event log -> T1/DPO. Hardware clock synchronization, stream alignment and a replay UI are TODO. |
| Determinism, historical trajectory reuse | partial | Training config fixes seeds; split hashes are stable; attempts and provenance are retained. Planner-level deterministic sampling and a successful-trajectory retrieval store remain TODO. |

## Benchmark catalog and implementation boundary

`benchmarks/catalog.csv` is the merged discovery catalog, not a set of downloaded evaluations. `scripts/benchmark_link.py::build_map` reads its actual columns (`id`, `name`, `track_fit`, `tasks`, `modality`, `source`, links/access/license/status) and local source/modality values. It writes one row per benchmark to `docs/benchmark_map.md`.

Track comes directly from `track_fit`. Explicit family matches identify local ORD, ChEMBL, PubChem BioAssay, QM9, Open X and DROID subsets. Other mappings mean related task interfaces, not ingestion or benchmark scores. New benchmarks need source-specific loaders, licensing, target definitions and contamination checks; protein/force/OCSR/agent benchmarks cannot be evaluated by merely reusing a provenance task. Catalog link checks and license hints are historical metadata, not fresh verification.

## Running and evidence

All ten training entry points accept `[config.yaml] --smoke` through `config.py::training_config`. `tiny.py::ensure_tiny_model` builds a small local GPT-2 plus byte tokenizer, so CPU checks do not depend on model downloads. These use the actual SFT/DPO/ORPO/RM/GRPO trainers and real data; encoder, alignment, projector, distillation, BC and world-model loops also run. `config.py::training_rows` selects short complete real examples for LLM smoke tests.

`profiling.py::{StepTimer,ProfileCallback}` writes step timings, losses where available, device memory, summaries and short torch traces. `bash scripts/smoke_all.sh` runs both tracks and writes `outputs/smoke_report.json`. `pytest` covers typed calls, Data/Error semantics, recovery rewards, logs, swept-point collisions, split boundaries, blind exclusions and same-split preferences. `scripts/make_notebooks.py` generates `notebooks/colab_{scientist,operator}.ipynb` for full A100 jobs from the current workspace snapshot.
